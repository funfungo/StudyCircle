# 新增 Git 选项与数据库迁移系统

- **时间**: 2026-03-22 18:00
- **对话 ID**: `不可用`

## 需求

注册表单新增"是否会使用 Git"选项，并希望有一个脚本能在前端调整表结构时自动同步数据库。

## 过程

1. 在 `RegistrationPage.jsx` 中新增 `GIT_LEVELS` 单选组和 `activity` 隐藏字段
2. 尝试通过 PostgreSQL 直连执行迁移，但 `db.xxx.supabase.co` 无法 DNS 解析（代理环境下 TCP 5432 端口不走 HTTP 代理）
3. 改为通过 Supabase Management API（HTTPS）执行 SQL，需要 Personal Access Token（`sbp_` 开头）
4. 提交表单报 RLS 错误：因为之前登录过管理后台，浏览器缓存了 `authenticated` 角色的 JWT，而 INSERT 策略只允许 `anon` 角色
5. 补充了 `authenticated` 角色的 INSERT 策略，问题解决

## 产出

- `scripts/migrate.mjs` — 数据库迁移脚本（通过 Supabase Management API）
- `supabase/migrations/0001_add_git_level.sql` — 新增 git_level 列
- `supabase/migrations/0002_add_activity.sql` — 新增 activity 列
- `supabase/migrations/0003_allow_authenticated_insert.sql` — 修复 RLS 策略
- `.cursor/skills/supabase-migration/SKILL.md` — 迁移 Skill
- `src/components/RegistrationPage.jsx` — 新增 Git 选项 + activity 字段
- `.env` — 新增 `SUPABASE_ACCESS_TOKEN` 配置

## 经验

- 代理环境下 PostgreSQL 直连不通（TCP 5432 不走 HTTP 代理），改用 HTTPS API 方案
- Supabase Management API 需要 Personal Access Token（`sbp_` 开头），不是 service_role key
- 浏览器中登录过 Supabase 后，客户端会缓存 JWT，后续请求自动使用 `authenticated` 角色，需要确保 RLS 策略覆盖该角色
